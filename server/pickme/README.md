# 픽미 초대 로컬 개발 서버

친구 픽업 초대 → 링크 열기 → 수락/거절 → 차 화면 반영을 시험하는 별도 개발 서버입니다. 딱픽업의 Firebase·매장·주문·내비 코드는 수정하지 않습니다. 기본 모드는 로컬 전용이며, 아래 Firebase 시연 모드에서는 친구 응답을 클라우드에 저장합니다. 차량 연결 서버는 여전히 로컬 개발용입니다.

## 실행 (Node.js 20 이상)

저장소 루트에서:

```bash
node server/pickme/server.mjs
```

컴퓨터 브라우저에서 http://127.0.0.1:8787/ 를 열면 운전자 테스트 화면이 나옵니다. 초대를 만들고 '친구 화면 열기'로 수락하면 운전자 화면이 약 2초 안에 바뀝니다.

## Pleos 에뮬레이터

1. 위 서버를 계속 켜 둡니다.
2. Android 앱을 실행하고 홈 → 픽미를 누릅니다.
3. 시연 연락처 4명에서 이름을 검색·선택하고 초대 링크를 만듭니다. Pleos 내비에 목적지를 먼저 설정하고 가져온 뒤 초대를 만듭니다.
4. 링크를 복사해서 **컴퓨터 브라우저**에서 열고 수락합니다. 앱 화면이 약 2초 안에 수락으로 바뀝니다.

Android 에뮬레이터는 호스트 컴퓨터의 `10.0.2.2:8787`에 연결합니다. 기본 친구 링크의 `127.0.0.1`은 컴퓨터 전용이며, 그대로 휴대폰이나 에뮬레이터 브라우저에서 열면 연결되지 않습니다.

팀 Firebase 설정인 `car-app/app/google-services.json`이 없는 경우, 이 로컬 기능만 시험할 때 아래처럼 `pickmeLocalInvites` 옵션으로 Firebase 설정 플러그인을 생략할 수 있습니다. 이 빌드에서는 **딱픽업 Firebase 기능을 시험할 수 없습니다**. 기본 빌드는 기존 Firebase 설정을 요구합니다. 가짜 Firebase 설정 파일을 만들지 않습니다.

```bash
cd car-app
# JAVA_HOME=JDK 21, ANDROID_HOME=로컬 SDK 경로
bash ./gradlew assembleDebug -PpickmeLocalInvites=true --max-workers=2
```

## 같은 Wi-Fi의 휴대폰에서 수락 시험

컴퓨터의 사설 IP를 확인하고 아래 주소를 실제 값으로 바꿉니다.

```bash
HOST=0.0.0.0 PUBLIC_BASE_URL=http://192.168.0.10:8787 node server/pickme/server.mjs
```

방화벽과 Wi-Fi의 기기 간 통신이 허용되어야 합니다. 서버를 이 설정으로 재시작한 후 **새 초대**를 만들어 공유합니다. 이 옵션은 개발 네트워크에서만 사용하며 인터넷에 공개하지 않습니다. 실제 운영은 HTTPS·인증·영구 저장소를 갖춘 서버 또는 팀 Firebase 연결이 필요합니다.

## 데이터와 제약

- 상태: `pending` → `accepted` 또는 `declined`. 같은 응답 재전송은 허용, 서로 다른 응답으로 변경은 거부합니다.
- 초대 유효기간 24시간. 기본 로컬 모드 데이터는 메모리에만 저장합니다. Firebase 모드에서도 운전자 세션은 서버 재시작 시 사라집니다. 단, `PICKME_STATE_FILE`을 설정한 배포 서버는 파일에 저장해서 유지합니다.
- 운전자 세션은 HttpOnly cookie, 친구 링크는 무작위 토큰(fragment)을 사용합니다. 친구는 다른 초대를 조회하거나 운전자 목록에 접근할 수 없습니다.
- 링크를 가진 사람은 응답할 수 있습니다. 링크를 비공개로 전달해야 합니다. 운영 인증을 대신하는 구조는 아닙니다.
- 자동 문자·카톡 발송과 실제 도로의 정차 가능 판정은 없습니다. 운전자 수락·공유 동의 이후 Pleos가 제공한 픽업 경유지 ETA를 공유하며 별도로 추정 계산하지 않습니다. GPS 기반 시연 후보 추천과 친구의 지도 선택은 아래 탑승 장소 선택 절을 따릅니다.
- 앱 화면 회전은 초대 상태를 유지하지만, 화면을 닫아도 같은 앱 프로세스에서는 진행 중인 초대를 복원합니다. 프로세스 종료 후에는 새 초대가 필요합니다.
- 친구 페이지는 다시 열어 같은 응답을 확인할 수 있습니다. 운전자 테스트 웹은 새로고침하면 새 세션이 만들어집니다.
- 차량 앱의 초대 화면과 HTTP 허용 설정(`10.0.2.2`만)은 debug·release 모두 포함됩니다(2026-11-12부터).

## 배포 서버 (Render, 심사 기간용)

심사위원이 컴퓨터에서 서버를 켜지 않아도 되도록 유료 서버(Render Starter)에 올려 둡니다. 설정은 저장소 맨 위 `render.yaml`에 있습니다.

1. Render에서 **New → Blueprint**를 고르고 이 저장소를 연결하면 `render.yaml`대로 서버와 디스크가 만들어집니다.
2. `sync: false` 항목(`PICKME_FIREBASE_WEB_API_KEY`, `PICKME_GMAIL_USER`, `PICKME_GMAIL_APP_PASSWORD`)은 Render 화면에 직접 입력합니다. 저장소와 단톡방에는 올리지 않습니다.
3. 배포가 끝나면 `https://<서비스 이름>.onrender.com/health`가 `{"ok":true,"mode":"deployed"}`를 돌려주는지 확인합니다.
4. 차량 앱의 서버 주소(`http://10.0.2.2:8787`)를 이 https 주소로 바꿉니다. (차량 앱 담당)

| 환경 변수 | 뜻 |
|---|---|
| `HOST=0.0.0.0` | 외부 접속 허용 (기본값 `127.0.0.1`은 내 컴퓨터 전용) |
| `PORT` | Render가 자동으로 넣어 줌 |
| `PICKME_STATE_FILE` | 운전자 세션·초대·서버의 Firebase 로그인 정보를 저장할 파일. 설정하면 서버를 재시작해도 기존 초대와 진행 중인 위치 공유를 이어서 씁니다. 파일에 초대 링크 토큰이 들어 있으므로 서버 디스크에만 둡니다 |

- 무료 플랜은 15분 동안 요청이 없으면 잠들고 깨는 데 약 1분이 걸려 시연 중 연결 실패가 나므로 Starter를 씁니다.
- 디스크를 붙인 서비스는 재배포할 때 수십 초 정도 끊길 수 있습니다. 시연 직전에는 재배포하지 않습니다.
- 로컬 개발은 기존처럼 `PICKME_STATE_FILE` 없이 실행하면 메모리만 씁니다.

## API

| 요청 | 역할 |
|---|---|
| GET `/api/demo/contacts` | 실제 전화번호 없는 시연 연락처 4명 |
| POST `/api/driver/session` | 로컬 운전자 세션 생성 |
| POST `/api/pickups` | 세션 소유 초대 생성 |
| GET `/api/pickups/{id}` | 해당 운전자만 상태 조회 |
| GET `/api/friend/invitation` | 링크 토큰으로 초대 조회 |
| POST `/api/friend/invitation` | 링크 토큰으로 수락/거절 |

HTTP 응답의 `error`는 화면 표시용 문구입니다. 친구 API는 `Authorization: Bearer <초대 토큰>`을 사용합니다. ID와 토큰은 서버가 생성하며 로그에 출력하지 않습니다.

## 연락처 기반 초대

POST `/api/pickups`에 `contactId`를 보내면 서버가 시연 목록에서 표시명을 정합니다. `meetingPoint`와 `destination`은 미정(null)입니다. 이전 테스트용 직접 입력 API도 호환되지만 새 앱·웹의 시작 흐름에서는 사용하지 않습니다.

## Firebase 친구 웹 시연

배포 주소: https://pickme-ca1cd-friend.web.app

주소만 열면 초대 링크 안내가 나옵니다. 차량 앱에서 만든 **전체 초대 링크**를 친구에게 전달해야 합니다. 친구는 같은 Wi-Fi가 아니어도 링크로 수락할 수 있습니다.

저장소 루트에서 중계 서버를 실행합니다:

```bash
PUBLIC_BASE_URL=https://pickme-ca1cd-friend.web.app PICKME_FIREBASE_DATABASE_URL=https://pickme-ca1cd-default-rtdb.asia-southeast1.firebasedatabase.app node server/pickme/server.mjs
```

컴퓨터의 운전자 테스트 화면은 http://127.0.0.1:8787/ 이며 Android 에뮬레이터는 기존처럼 10.0.2.2:8787을 사용합니다. 차량 앱에 API 키를 입력할 필요는 없습니다. 실시간 공유는 아래 로컬 `.env` 설정이 필요합니다.

- 친구 웹만 Firebase Hosting에 배포됩니다. 차량 연결 중계 서버를 끄면 차량의 초대 생성·응답 확인은 중단됩니다.
- 운전자 세션·초대 연결 정보는 메모리이므로 서버 재시작 후에는 새 초대를 만듭니다.
- RTDB의 `pickmeInvites`와 인증된 서버가 쓰는 `pickmeLive`를 사용합니다. 기존 `stores`·`orders` 규칙은 유지합니다.
- 현재는 고정된 시연 연락처 4명만 허용합니다. 실제 전화번호부·운영 인증은 구현하지 않았습니다. 친구가 허용한 GPS와 탑승 장소 처리는 아래 절을 따릅니다.
- 무작위 링크를 가진 사람이 조회·응답할 수 있고 전체 목록 조회는 거부합니다. 24시간 뒤 접근은 차단하지만 데이터 자동 삭제 기능은 없습니다.
- 친구의 응답은 한 번만 저장되며 기존 연락처·이름·유효기간 수정은 거부합니다.

재배포와 규칙 검증:

```bash
firebase emulators:exec --only database --project demo-pickme-invites --config firebase.emulators.json 'node --test server/pickme/firebase-rules.test.mjs server/pickme/server.test.mjs'
firebase deploy --only hosting,database --project pickme-ca1cd --config firebase.friend.json
```

기본 Hosting 사이트 대신 친구 전용 사이트에 배포합니다. 기존 팀 데이터베이스 규칙을 다시 확인한 뒤 배포해야 합니다.

## 탑승 장소 선택 (2026-11-05)

친구는 위치 확인 버튼을 눌러 GPS를 한 번 제공하고 추천 장소에 동의하거나, 지도에서 핀을 옮겨 탑승 장소를 확정합니다. 위치 권한을 거절해도 수동 선택이 가능합니다. "아니오"는 위치 변경입니다.

- 현재 후보: 한양대학교 **서울캠퍼스** 정문 부근 임시 좌표, 그리고 에뮬레이터 차량 기본 위치(판교 제2테크노밸리) 주변 시연 후보 7곳(판교 제2·1테크노밸리 주차장, 판교역, 현대백화점 판교점, 백현동 카페거리 공영주차장, 시흥동 행정복지센터 부근). 판교 후보는 OpenStreetMap 좌표이며 정확한 승하차 핀과 정차 적법성은 현장 확인 전입니다.
- 추천은 500m 안의 등록 후보와 주차장을 함께 모아 가까운 순서로 최대 3곳을 보냅니다. 주차장 검색이 실패하면 등록 후보만 보냅니다.
- 주차장 검색은 `.env`에 `KAKAO_REST_API_KEY`가 있으면 **카카오 로컬 API**(카테고리 PK6, 약 1초), 없으면 **Overpass**를 씁니다. 서버를 켤 때 어느 쪽을 쓰는지 한 줄로 표시합니다. Overpass 공용 서버는 2026-11-11 시험에서 응답에 약 28초가 걸려 시간 초과(12초)로 실패했습니다.
- `server/pickme/pickup-candidates.json`에서 팀이 후보를 관리합니다. 후보 수정 시 Firebase의 proposal/pickupPoint 검증 규칙도 함께 변경·검증해야 합니다. 현재 후보를 확정한 운영 데이터처럼 사용하지 않습니다.
- 500m 안의 후보를 직선거리로 고릅니다. 해당 지역 밖에서는 수동 선택을 안내합니다. 실제 차량 경로와 도보 거리, 최적 도착 시간은 아직 계산하지 않습니다.
- GPS 확인은 HTTPS 또는 localhost에서 가능합니다. "한양대 시연 모드"는 실제 GPS와 구분된 가상 위치로 추천 흐름을 시험합니다.
- Firebase 모드에서 locationRequest → 로컬 서버가 약 2초마다 처리 → proposal → 친구가 pickupPoint 확정 및 accepted 순서입니다. 서버가 꺼져 있으면 추천은 시간 초과 안내를 표시하고 직접 선택은 가능합니다.
- 확정 시 원래 GPS 요청·추천은 삭제합니다. 장소 선택 결과는 확정한 pickupPoint와 meetingPoint로 전달합니다. 친구 확정만으로 내비를 바꾸지 않으며, 운전자 수락 후 경유지를 추가하고 차량 위치를 공유합니다. SMS 자동 발송은 없습니다.
- 지도에서 선택한 장소는 정차 가능으로 자동 판정하지 않습니다. 별도 확인 없이 추천 후보로 등록하지 마세요.

검증:

```bash
firebase emulators:exec --only database --project demo-pickme-invites --config firebase.emulators.json 'node --test server/pickme/firebase-rules.test.mjs server/pickme/server.test.mjs server/pickme/pickup-planner.test.mjs'
```

## Pleos 목적지 스냅샷

차량 앱에서 Pleos 목적지를 설정하면 초대 화면이 현재 위치와 목적지를 자동으로 가져옵니다. 연결되지 않으면 다시 연결을 시도합니다. 초대 생성의 선택 필드 `trip`에는 origin, destination(label/latitude/longitude), source(pleos/demo), capturedAt, 선택 heading을 담습니다. 5분 이상 지난 정보는 거절합니다. 현재 위치·목적지 좌표는 로컬 서버 메모리에만 두고 Firebase에는 journey.destinationLabel/source만 저장합니다. 이 초대 스냅샷에는 차량 좌표를 공개하지 않습니다. 이후 운전자가 수락하고 위치 공유를 시작하면 최신 차량 위치를 친구에게 공유합니다.

현재 단계는 정보 연결입니다. 후보별 도로 반대편·유턴·우회 시간 비교와 현재 Pleos 경로의 자동 갱신은 구현하지 않았습니다. routeStatus가 pleos-context-only이면 목적지만 연결된 것이며 경로 최적화 결과가 아닙니다. 후보별 경로 최적화는 하지 않습니다. 친구 웹에 표시하는 예상 경로선에는 카카오모빌리티 길찾기를 별도로 사용하며 실제 Pleos 경로와 다를 수 있습니다.

Overpass 주차장 검색은 접근 제한·노상 주차·시간 제한이 표시된 곳을 제외하고 접근 허용 표기를 우선합니다. 운영시간·요금·승하차 허용 여부가 없으면 미확인으로 표시합니다. 시설 대표 좌표가 출입구를 뜻하지는 않습니다. 공개 API의 실제 연결 시험은 406/시간 초과로 실패하여, 실사용 추천 완료 상태가 아닙니다. 오류 시 unavailable을 반환하고 수동 선택을 안내합니다.

## 차량에서 확정 장소로 이동 요청

친구가 장소를 확정하면 차량 픽미 화면에 `픽업 수락 · 안내 시작`이 표시됩니다. Pleos 내비에서 최종 목적지를 먼저 설정·안내한 상태여야 합니다. 버튼을 누르면 현재 목적지와 경유지를 읽고 `addWaypoint(SECOND)`를 요청합니다. 매장 FIRST 및 최종 목적지를 다시 설정하는 API는 호출하지 않습니다. 기존 친구 경유지가 있으면 바뀔 수 있습니다.

반영 뒤 내비에서 경유지와 목적지를 다시 읽어 확인합니다. 현재 Pleos 에뮬레이터는 경유지 좌표를 0,0으로 반환하므로 이 경우에는 이름 반영만 확인하고 지도 확인을 안내합니다. 유효한 좌표가 반환되는 환경에서는 좌표까지 비교합니다. POI ID 없는 좌표 요청이 서비스에서 거절되는 경우에는 오류를 표시합니다. FIRST를 대신 차지하거나 가짜 POI ID를 생성하지 않습니다. 현재 기능은 debug·release 모두 같은 초대 화면에 연결됩니다.

## 운전자 수락 · 실시간 위치 공유

친구가 장소를 확정한 뒤 차량에서 픽업을 수락합니다. `픽업 수락 · 안내 시작`은 위치 공유 서비스를 준비하며, 내비 경유지 반영이 확인된 뒤 차량 위치 전송이 시작됩니다. 약 5초마다 Pleos 현재 위치와 픽업 경유지 ETA를 읽고, 친구 웹은 약 3초마다 최신 데이터를 확인합니다. 정보가 20초 이상 오래되면 ETA를 숨기고 오래된 위치임을 표시합니다. 위치 공유 중지 버튼이나 알림의 중지 동작으로 끌 수 있습니다.

### 카카오 주차장 검색 키 (선택)

1. https://developers.kakao.com 에 로그인해 **앱 → 앱 생성**으로 앱을 만듭니다(카테고리: 지도/내비게이션).
2. 앱의 왼쪽 메뉴 **앱 → 플랫폼 키**에서 **REST API 키**를 복사합니다.
3. 왼쪽 메뉴 **제품 설정 → 카카오맵**에서 사용 설정을 **ON**으로 바꿉니다.
4. `server/pickme/.env`에 `KAKAO_REST_API_KEY=복사한키`를 넣고 서버를 다시 켭니다. 첫 줄에 `주변 주차장 검색: 카카오 로컬`이 보이면 연결된 것입니다.

같은 키로 **카카오모빌리티 길찾기**도 사용해, 차량이 오는 동안 친구 웹 지도에 차량 → 카페 → 탑승 장소의 예상 도로 경로(파란 선)를 그립니다. 키가 없으면 경로선 없이 동작합니다.

키는 `.env`에만 두고 Git·채팅에 공유하지 않습니다. 주변 주차장 검색에는 반올림한 검색 좌표를 사용합니다. 예상 경로선 계산에는 차량·카페·탑승 장소 좌표를 카카오모빌리티에 전달하며, 초대 링크나 사람 이름은 보내지 않습니다. 화면에는 출처로 '카카오맵'을 표시합니다.

Firebase Authentication에서 익명 로그인을 먼저 설정해야 합니다. 서버용 익명 계정이며 친구의 로그인 화면은 없습니다. Firebase Web SDK 설정의 API key를 로컬 `server/pickme/.env`의 PICKME_FIREBASE_WEB_API_KEY에 넣고 다음처럼 실행합니다. 실제 값은 Git에 올리지 않습니다.

```bash
node --env-file=server/pickme/.env server/pickme/server.mjs
```

PUBLIC_BASE_URL과 PICKME_FIREBASE_DATABASE_URL도 같은 파일에 설정합니다. 이름만 있는 예시는 .env.example에 있습니다. 웹에는 API key나 서버 인증 토큰을 포함하지 않습니다. 새 초대의 trackingOwnerUid가 있어야 해당 초대의 차량 데이터를 쓸 수 있습니다. 인증 설정 전의 이전 초대는 새로 만들어야 합니다.

공유는 최대 1시간이며 서버 세션 재시작 후에는 새 초대를 만들어야 합니다. 정상 중지 시 최신 위치를 제거합니다. 비정상 종료 시 마지막 위치가 남아 있을 수 있지만 조회 유효기간 후 접근은 막힙니다. 운영 데이터 자동 삭제는 아직 없습니다. 위치가 고정된 에뮬레이터는 화면에서도 고정된 위치로 보이며, 화면 확인용 가상 데이터와 실제 SDK 검증을 구분해야 합니다.

| API | 의미 |
|---|---|
| POST /api/pickups/{id}/driver-accept | 운전자 소유 세션으로 픽업 수락 및 공유 동의 설정 |
| POST /api/pickups/{id}/live | 소유 운전자만 최신 위치·픽업 ETA 갱신 또는 중지 |
| GET /api/friend/live | 로컬 개발 모드의 친구용 최신 정보 조회 |

클라우드 친구 웹은 pickmeLive/{초대키}/public만 읽습니다. 다른 사용자 UID의 쓰기·비인증 쓰기·전체 목록 조회는 거부합니다. 인증·데이터베이스 규칙 시험은 두 에뮬레이터를 함께 사용합니다.

```bash
firebase emulators:exec --only database,auth --project demo-pickme-invites --config firebase.emulators.json 'node --test server/pickme/firebase-rules.test.mjs server/pickme/live-rules.test.mjs server/pickme/live-tracking.test.mjs server/pickme/live-api.test.mjs'
```

## 초대 이메일 발송

시연 운전자는 김픽미로 고정합니다. 친구 연락처를 선택한 뒤 발송을 확인합니다. 수신 주소는 연락처에 연결된 주소로 자동 결정됩니다.
서버 .env에 PICKME_GMAIL_USER와 PICKME_GMAIL_APP_PASSWORD를 직접 설정합니다. Google 2단계 인증 후 생성한 앱 비밀번호를 사용하며 Git이나 채팅에 공유하지 않습니다. PUBLIC_BASE_URL은 HTTPS 친구 Hosting 주소여야 합니다. 서버 재시작 후 새 초대를 만듭니다.

초대 소유자만 발송할 수 있고 초대당 1회 요청, 운전자 세션당 시간당 최대 5회입니다. 세션·횟수 제한은 메모리 기반으로 운영용 사용자 인증을 대신하지 않습니다. SMTP 접수는 받은편지함 도착 보장이 아닙니다. 오류·시간 초과도 접수됐을 수 있어 자동 재시도하지 않습니다. 수신함과 스팸함을 먼저 확인하고 필요하면 새 초대를 만듭니다. 수신 주소는 Firebase나 로그에 저장하지 않습니다.

실제 수신 주소는 서버의 비공개 `PICKME_MAIL_RECIPIENTS_JSON`에 등록합니다. 공개 JSON은 테스트용 예시이며 실제 발송 설정이 아닙니다.

## 연락처 초대 · 준비 완료 · 도착 안내

시연 연락처는 친구 1·친구 2·친구 3·친구 4 네 명입니다. 이름과 수신 이메일은 비공개 환경 설정에서 매칭하며 클라이언트가 임의 수신자를 지정할 수 없습니다. 연락처 선택 후 확인하면 초대를 만들고 메일을 발송합니다.

친구가 수락한 후 탑승 장소 도착 · 준비 완료를 누르면 pickmeReady/{초대키}/readyAt에 서버 시각이 한 번 저장됩니다. 위치 자동 판정이 아닌 탑승자의 직접 신고입니다. 차량 화면은 수락 이후에도 약 2초마다 상태를 확인합니다. 새 웹과 해당 Firebase 규칙을 함께 배포해야 합니다.

초대 메일이 접수된 초대만 위치 공유 중 유효한 Pleos 픽업 경유지 ETA가 처음 300초 이하가 되면 같은 수신자에게 도착 메일을 한 번 요청합니다. 첫 ETA가 5분 이내여도 발송합니다. SDK에서 20초 넘게 지난 ETA는 사용하지 않습니다. ETA가 없거나 공유 중지·만료인 경우 발송하지 않습니다. 메일 장애 시 중복 발송을 피하려고 자동 재시도하지 않으며 실제 메일 도착 시각은 보장하지 않습니다. 서버 재시작 시 초대 세션 자체가 사라지므로 새 초대가 필요합니다.

픽업 수락 시 위치·ETA 공유를 함께 시작하고 별도 체크박스는 사용하지 않습니다. 공유 중지는 유지합니다. 메일은 운전자·초대받는 사람·목적지를 HTML과 텍스트에 함께 표시합니다. 목적지가 없으면 아직 미정으로 표시합니다. 운전자 이름은 사용자가 입력한 표시명이며 본인 인증된 신원을 뜻하지 않습니다. HTML 특수문자를 이스케이프합니다.

메일의 기본 버튼과 하단 주소는 같은 HTTPS 초대 링크를 사용하는 실제 앵커입니다. 모바일 메일 앱 호환을 위해 테이블 기반 버튼을 사용합니다. 링크의 fragment 초대키는 유지합니다. 메일 앱의 스팸·피싱 차단은 HTML에서 해제할 수 없으므로 신뢰하는 팀 발신 메일인지 확인 후 받은편지함에서 다시 시험합니다. 변경된 메일 디자인은 새로 발송하는 메일에만 적용됩니다.


## 친구 웹의 카페 경유 표시

운전자가 픽미 수락 후 딱픽업에서 카페를 추가하면, 현재 Pleos 경유지 목록에서 **선택한 카페가 친구 탑승 장소 앞에 있는지** 확인한 뒤 `pickmeLive/{초대키}/public/cafeVisit`에 공유합니다. 카페 선택만으로 경로 반영이 완료됐다고 표시하지 않습니다.

- `name`: 카페 이름, `phase`: `before_pickup` / `at_cafe` / `passed`
- `position`: 내비에 추가 요청한 카페 좌표(있을 때만). 지도에는 카페 핀과 옆모습 자동차 아이콘을 표시합니다.
- 카페 도착 이벤트와 남은 경유지 목록을 함께 확인해 경유 상태를 갱신합니다. 음료 수령 완료를 자동으로 판단하지 않습니다.
- 예상 시간은 **친구 경유지까지의 Pleos ETA**로 카페 주행 경유를 반영하지만, 알 수 없는 매장 대기 시간은 포함하지 않습니다.
- 오래된 경유 정보, 경로 취소·카페 제거, 공유 중지는 화면에서 숨깁니다. 쓰기 권한은 기존 초대 소유 서버로 유지합니다.

배포 시 친구 Hosting과 데이터베이스 규칙을 함께 갱신하고 중계 서버·차량 APK도 새 코드로 실행해야 합니다. 이 변경은 방문 순서·매장 추천·주문 예약 계산을 바꾸지 않습니다.

## 제출용 개인정보 분리

- `PICKME_MAIL_RECIPIENTS_JSON`: 비공개 JSON 배열. 예: `[{"name":"친구 1","email":"friend@example.com"}]`. 표시 이름은 `demo-contacts.json`과 같아야 합니다. 환경 변수 값은 Git에 커밋하지 않습니다.
- 비공개 수신자 설정이 없으면 서버 시작 시 이메일 발송을 비활성화합니다. 공개 `demo-mail-recipients.json`은 모의 전송 테스트용입니다.
- 실명 제거로 연락처 표시명과 Firebase 검증 규칙이 함께 바뀌었습니다. 배포 시 새 서버·새 APK·`firebase/database.rules.json`을 맞추고 새 초대로 확인합니다. 기존 테스트 서버·배포 규칙은 이 저장소 생성만으로 바뀌지 않습니다.
- 이 제출용 사본은 `state-store.mjs` 누락을 보완했습니다. 상태 파일은 권한 600으로 원자적으로 저장하고 손상된 기존 파일을 덮어쓰지 않습니다. 실제 Render 배포·재배포 검증은 별도로 필요합니다.
