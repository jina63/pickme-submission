# 픽미 중계 서버

차량 앱과 동승자 웹 사이에서 초대·응답·추천·차량 정보·이메일 요청을 연결하는 Node.js 중계 서버입니다. 제출 앱은 HTTPS 배포 서버를 사용하며 서버 코드는 로컬 개발에도 사용할 수 있습니다. 매장 주문은 이 서버를 거치지 않고 차량 앱이 Firebase에 직접 저장합니다.

## 실행과 환경 설정

제출 차량 앱의 기본 연결 주소는 **https://pickme-relay.onrender.com**입니다. 서버가 배포되어 있으면 심사위원 컴퓨터에서 별도 서버를 실행하지 않습니다. 아래 명령은 서버를 직접 운영하거나 로컬에서 개발할 때 사용하는 절차입니다.

Node.js 20 이상을 사용하며 `--env-file`을 지원하는 버전이 필요합니다. 저장소 루트에서 의존성을 설치하고 실행합니다.

```bash
npm ci --prefix server/pickme
node server/pickme/server.mjs
```

기본 주소는 `http://127.0.0.1:8787/`이며 운전자 테스트 웹을 제공합니다. 이 모드는 초대·응답을 로컬 메모리에서 처리합니다. `.env`·이메일 없이도 초대 링크를 복사해 컴퓨터 브라우저에서 응답하는 시험이 가능합니다. 테스트 웹을 새로고침하면 운전자 세션이 바뀝니다.

Firebase 연결·메일을 사용하는 경우 `.env.example`을 기준으로 로컬 `.env` 또는 배포 환경 변수를 설정합니다. 실제 수신자는 `PICKME_MAIL_RECIPIENTS_JSON`에 등록하며 공개 예시 JSON은 실제 발송 설정이 아닙니다.

| 환경 변수 | 용도 |
| --- | --- |
| `HOST`·`PORT` | 기본 `127.0.0.1`·`8787` |
| `PUBLIC_BASE_URL` | 생성할 동승자 링크의 기본 주소. 메일에는 HTTPS 주소 필요 |
| `PICKME_FIREBASE_DATABASE_URL` | 클라우드 초대·공유 DB |
| `PICKME_FIREBASE_WEB_API_KEY` | 서버용 익명 인증. Firebase Authentication 익명 로그인 설정 필요 |
| `PICKME_GMAIL_USER`·`PICKME_GMAIL_APP_PASSWORD` | Gmail SMTP 발신 계정·앱 비밀번호 |
| `PICKME_MAIL_RECIPIENTS_JSON` | 등록 연락처 표시명과 일치하는 비공개 수신자 배열. 미설정 시 메일 비활성화 |
| `PICKME_STATE_FILE` | 초대·세션·서버 인증 상태를 보관할 비공개 영속 파일. 미설정 시 메모리 모드 |
| `PICKME_CONTACTS_FILE` | 서버 폴더 기준 로컬 연락처 파일. 미설정 시 기본 시연 연락처 사용 |
| `KAKAO_REST_API_KEY` | 주차장 검색·예상 도로 경로 계산 |

```bash
node --env-file=server/pickme/.env server/pickme/server.mjs
```

클라우드 모드에서는 `PUBLIC_BASE_URL`을 친구 Hosting 주소로 설정합니다. 웹만 Hosting에서 제공되며 차량 연결 중계 서버는 계속 실행해야 합니다. DB 구조·권한·규칙 배포는 [Firebase 안내](../../firebase/README.md), 웹 배포·표시는 [동승자 웹 안내](../../web/friend/README.md)에서 관리합니다. 비밀 값·개인 연락처는 커밋하지 않습니다.

## 제출 환경과 시연 영상

제출본에는 비밀 설정을 포함한 `.env` 파일을 제공하지 않습니다. Gmail·Firebase·수신자 설정은 배포 서버의 비공개 환경 변수로 관리하므로, **제출 컴퓨터에 `.env`가 없다는 이유로 이메일 기능이 비활성화되는 것은 아닙니다.** 실제 이메일 발송은 배포 서버의 발신·수신자 설정과 메일 서비스 상태에 따릅니다.

| 구분 | 제출 앱·시연 영상 | 별도 로컬 개발 |
| --- | --- | --- |
| 서버 | HTTPS 배포 서버 사용 | 개발 컴퓨터에서 Node.js 서버 실행 |
| 비밀 설정 | 배포 서버에만 보관 | 필요한 기능에 맞춰 로컬 `.env` 준비 |
| 초대 전달 | 공개 HTTPS 링크·QR, 서버 설정이 있는 경우 이메일 | 기본 무설정 모드는 로컬 링크 복사 |
| 응답 저장 | 배포 서버의 Firebase·영속 상태 설정 사용 | Firebase·상태 파일 미설정 시 서버 메모리 |
| 위치 | 링크를 연 휴대폰의 위치 권한 사용 | 컴퓨터 브라우저로 열면 컴퓨터 기준 위치 |

**제출본 확인 절차**

1. 인터넷에 연결된 Pleos 에뮬레이터에 제출 앱을 설치하고 내비 목적지를 설정합니다.
2. 픽미에서 친구를 선택해 초대를 만듭니다. QR·링크는 심사위원이 동승자 웹을 확인하는 수단이며, 이메일은 실제 수신자에게 초대 내용을 전달하는 시연입니다.
3. 휴대폰에서 QR 또는 전체 HTTPS 링크를 열어 탑승 장소를 확정합니다.
4. 차량에서 응답을 확인하고 픽업을 수락한 뒤 위치·ETA·카페 경유 정보를 확인합니다.

QR은 링크 전달 방식이며 문자 자동 발송 기능이 아닙니다. 실제 전화번호 목록과 메시지 발송은 이번 작업에서 확장하지 않습니다. 시연 영상도 배포 서버의 비공개 설정을 사용하는 환경에서 촬영하되 키·비밀번호·실제 수신자 정보는 노출하지 않습니다.

이 구분은 픽미 초대·응답에 해당합니다. 딱픽업의 차량 앱 Firebase 연결은 중계 서버 환경 설정과 별도입니다.

## 차량 연결과 로컬 시험

차량 앱의 초대 화면과 위치 공유 서비스는 모두 `https://pickme-relay.onrender.com`을 사용합니다.

서버 자체를 로컬에서 시험할 경우 기본 주소는 `127.0.0.1:8787`입니다. 이 주소의 초대 링크는 해당 컴퓨터 전용이며 휴대폰 접속을 대체하지 않습니다. 휴대폰에서 로컬 서버를 사용하려면 접근 가능한 서버 주소·HTTPS·네트워크 설정을 별도로 구성해야 합니다. 제출 앱이 그 로컬 서버에 자동 연결되는 것은 아닙니다.

차량 빌드·설치·권한은 [차량 앱 안내](../../car-app/README.md), Firebase 설정 없이 로컬 초대만 확인하는 별도 개발 옵션은 [개발용 빌드와 테스트](../../car-app/README.md#개발용-빌드와-테스트)에서 관리합니다.

## 배포와 재시작 상태 저장

저장소 루트의 `render.yaml`은 Node.js 서비스·`/health`·비공개 영속 디스크와 `PICKME_STATE_FILE`을 설정하는 배포 구성입니다. 현재 차량 앱에 배포 주소를 적용했으며 `/health`에서 `ok: true`, `mode: deployed` 응답을 확인했습니다. 배포 담당자가 제공한 검증 결과에 따르면 Firebase 규칙 적용, 서버의 초대 생성, 재시작 후 기존 초대 유지가 확인되었습니다. 차량·휴대폰·매장 웹을 연결한 정상 시나리오의 확인 결과와 예외 상황의 향후 보완 방향은 [APK 안내](../../apk/README.md#파일-확인과-검증-범위)에서 관리합니다.

`state-store.mjs`는 지정한 상태 파일에 초대·운전자 세션을 보관합니다. 서버용 Firebase 인증도 같은 저장소를 이용해 재시작 후 UID를 유지합니다. 상태 파일은 세션 자격 정보를 포함하므로 비공개 저장 공간에 두고 커밋하지 않습니다. 파일은 제한 권한으로 원자적으로 저장하며 손상된 기존 파일은 덮어쓰지 않고 시작을 중단합니다.

영속 파일·같은 클라이언트 쿠키·유효기간이 유지되어야 기존 연결을 이어갈 수 있습니다. 기본 제출 앱은 배포 서버를 사용하며, 상태 파일 없이 직접 실행하는 로컬 개발 모드에서만 서버 재시작 시 상태가 사라집니다.

## 요청 처리와 API

운전자 API는 소유 세션 쿠키, 로컬 동승자 API는 초대 토큰으로 접근합니다. 클라우드 동승자 웹은 DB 규칙을 통해 응답·추천 요청·준비 상태를 처리하며 서버가 이를 연결합니다. 토큰·초대 ID와 수신 주소를 로그에 노출하지 않습니다.

| 주요 요청 | 역할 |
| --- | --- |
| GET `/health` | 서버 상태 |
| GET `/api/demo/contacts` | 공개 표시용 등록 연락처 |
| POST `/api/driver/session` | 운전자 세션 생성 |
| GET `/api/driver/mail-recipients` | 운전자용 수신 대상 정보 |
| POST `/api/pickups` | 초대 생성 |
| GET `/api/pickups/{id}` | 소유 운전자의 상태 조회 |
| POST `/api/pickups/{id}/email` | 초대 메일 요청 |
| POST `/api/pickups/{id}/driver-accept` | 운전자 수락·공유 동의 |
| POST `/api/pickups/{id}/live` | 차량 정보 갱신·중지 |
| GET·POST `/api/friend/invitation` | 로컬 초대 조회·응답 |
| POST `/api/friend/recommendation` | 로컬 탑승 후보 요청 |
| GET·POST `/api/friend/ready` | 로컬 준비 상태 조회·입력 |
| GET `/api/friend/live` | 로컬 차량 정보 조회 |

초대는 `pending`에서 `accepted` 또는 `declined`로 전환합니다. 같은 응답 재전송은 허용하지만 서로 다른 응답으로 변경하지 않습니다. 실제 위치 공유의 조건은 [픽미 안내](../../car-app/app/src/main/java/com/pickme/car/pickme/README.md#차량-정보-공유), 후보 선정·외부 제공자 전환은 [웹의 추천 안내](../../web/friend/README.md#장소-선택과-추천)를 참고합니다.

## 이메일 처리

- 수신자는 `PICKME_MAIL_RECIPIENTS_JSON`의 비공개 배열로 지정합니다. 예시 형식은 `[{"name":"친구 1","email":"friend@example.com"}]`이며 표시명은 등록 연락처와 일치해야 합니다. 실제 값을 커밋하지 않습니다.
- 수신자 설정이 없으면 Gmail 설정이 있어도 이메일 발송은 비활성화됩니다. 클라이언트가 임의 주소를 지정하지 않습니다.
- 초대 메일은 소유자만 요청하며 초대당 1회·운전자 세션당 시간당 최대 5회로 제한합니다.
- SMTP 접수는 실제 받은편지함 수신을 보장하지 않습니다. 오류·시간 초과에도 접수됐을 수 있어 자동 재시도하지 않습니다.
- 도착 메일은 초대 메일이 접수된 초대에 대해, 공유 중인 유효한 Pleos 경유지 ETA가 처음 300초 이하가 되면 같은 수신자에게 한 번 요청합니다. 최초 ETA가 이미 5분 이내인 경우도 포함합니다.
- 공유 중지·만료·ETA 부재 또는 20초 넘게 오래된 ETA에서는 도착 메일을 요청하지 않습니다.

## 실행하고 시험하기

```bash
node --test server/pickme/server.test.mjs
```

Firebase·인증 통합 시험은 [Firebase 안내](../../firebase/README.md#규칙-검증과-적용)를 따릅니다. 서버가 설정된 상태에서 `node server/pickme/cafe-demo.mjs`를 실행하면 제어된 공유 데이터로 웹 상태를 시험할 수 있습니다. 이 도구는 설정된 DB에 시연 데이터를 기록하지만 메일·매장 주문 API는 호출하지 않으며 실제 주행 검증을 대신하지 않습니다. 기존 결과는 [검증 기록](../../docs/verification-2026-11-07.md)과 [결정 기록](../../docs/decisions.md)을 참고합니다.

## 한계와 보완점

`PICKME_STATE_FILE` 미설정 모드는 메모리 기반이므로 서버 재시작 후 새 초대가 필요합니다. 배포 환경에서는 재시작 후 기존 초대 유지가 확인되었습니다. 향후에는 재배포 시 복원 절차와 앱 프로세스 종료 후 클라이언트 세션 복구, 통신 장애 안내·재연결 흐름을 보완할 예정입니다. 운영용 사용자 인증 보완이 필요하며, 연락처 표시명은 클라우드 초대 규칙과도 일치해야 합니다. 데이터 권한·만료 처리는 Firebase 문서에서 관리합니다.
