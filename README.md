
1. Pleos 내비에서 목적지를 설정하고 안내를 시작합니다.
2. 홈에서 **딱픽업** → 메뉴 선택 → 추천 매장 확인 → 주문 진행을 확인할 수 있습니다.
3. **픽미 실행**: 같은 컴퓨터에서 중계 서버를 켠 뒤(아래), 홈 → 픽미 → 친구 초대 → 친구가 링크에서 탑승 장소 확정 → 수락 순서로 진행합니다.

```bash
cd server/pickme && npm install && cd ../..
node server/pickme/server.mjs   # Node.js 20 이상, .env 없이 로컬 모드로 실행
```

에뮬레이터 앱은 컴퓨터의 서버에 `10.0.2.2:8787`로 접속합니다. 초대 화면의 **링크 복사**로 받은 친구 링크를 컴퓨터 브라우저에서 열어 탑승 장소를 정하고 응답하면 차 화면에 수락 요청이 뜹니다. (이메일 발송은 선택 기능이라 `.env` 없이도 시연할 수 있습니다.) 서버가 꺼져 있으면 픽미 화면에 서버 연결 안내가 표시됩니다.

## 초대 전달 방식: 목표·시연·심사 재현

| 구분 | 전달 방법 | 현재 상태 |
|---|---|---|
| 서비스 목표 | 차량에서 연락처를 선택하면 친구의 전화번호로 문자 메시지에 초대 링크 전송 | 문자 발송 미구현 · 후속 개발 예정 |
| 현재 시연 영상 | 이메일로 초대 링크를 전달하고 친구가 링크를 열어 참여 | 구현됨 · 메일 서버 설정 필요 |
| 심사위원 직접 재현 | 차량 화면의 QR을 휴대폰으로 스캔해 같은 초대 링크 열기 | QR 표시 구현 · 휴대폰 실물 스캔 확인 예정 |

QR은 최종 서비스의 문자 초대를 대체하는 기능이 아니라, 심사위원이 팀원의 메일함에 접근하지 않고 **문자로 받은 링크를 열었을 때의 친구 웹 화면과 이후 흐름을 재현**하기 위한 보조 수단입니다. 이메일·QR 어느 방식으로 열어도 같은 초대에 연결하며, 이후 탑승 장소 선택·운전자 수락·차량 위치와 도착 시간 확인·준비 완료 흐름은 같습니다.

시연 설명: “실제 서비스는 문자로 링크를 전달하는 것을 목표로 합니다. 현재 프로토타입은 이메일로 시연하며, 심사 시에는 차량 화면의 QR로 같은 초대 링크를 열어 친구 화면을 확인하실 수 있습니다.”

차량에서 초대를 만든 뒤 **휴대폰으로 초대 열기 · QR**을 누릅니다. QR은 이메일과 같은 초대 링크를 앱 안에서 생성하며, 외부 QR 생성 서비스로 링크를 보내지 않습니다. 문자 수신·발송을 시연하는 기능은 아닙니다.

휴대폰에서 시험하려면 공개 HTTPS 친구 웹 주소와 연결된 중계 서버가 필요합니다. `127.0.0.1` 로컬 링크를 QR로 바꾸는 것만으로 다른 휴대폰에서 연결되지는 않습니다.

## 현재 구현 상황

### 픽미 — 친구 픽업

- **친구 초대:** 기본 연락처 4명 중 친구를 선택하고, 확인창을 거쳐 등록 이메일로 초대 링크를 보냅니다. 링크 복사·공유도 가능합니다. 시연 운전자 이름은 `김픽미`입니다.
- **목적지 연결:** 초대 전에 Pleos 내비의 차량 위치와 목적지를 자동으로 가져옵니다.
- **탑승 장소 선택:** 친구는 앱 설치·회원가입 없이 웹 링크를 열어 장소 검색, 현재 위치 확인, 지도 핀 이동으로 만날 장소를 확정합니다. '내 위치 사용'이나 장소 검색 뒤에는 지도 아래에 '주변에서 타기 좋은 곳' 목록이 나와, 누르면 바로 만날 장소로 바뀝니다.
- **주변 후보 추천:** 친구가 '내 위치 사용'을 누르거나 장소를 검색하면, 그 주변 500m(걸어서 약 7분) 안의 팀 등록 후보와 주차장을 가까운 순서로 최대 3곳 보여줍니다. 주차장은 **카카오 로컬 API**(서버 `.env`에 `KAKAO_REST_API_KEY`가 있을 때)에서 실제 이름으로 가져오고, 키가 없으면 OpenStreetMap(Overpass)을 씁니다. 현재는 직선거리 기준이며, 차량 진입 방향이나 정차 가능 여부까지 판단하지는 않습니다.
- **내비 연결:** 운전자가 픽업을 수락하면 친구의 탑승 장소를 SECOND 경유지로 추가하고 반영 결과를 확인합니다.
- **위치·도착 시간 공유:** 경유지 확인 후 차량 위치와 픽업 예상 시간을 약 5초마다 갱신합니다. 공유 중지와 연결 지연·종료 안내도 지원합니다.
- **카페 경유 공유:** 딱픽업 카페가 내비 경로에서 친구보다 앞에 확인되면 친구 웹에 카페 이름·경유 상태와 가게 모양 카페 핀을 표시하고, 친구 도착 시간에도 카페 경유가 반영됩니다. 예상 시간에는 알 수 없는 매장 대기 시간이 포함되지 않습니다.
- **예상 경로선:** 차량이 오는 동안 친구 웹 지도에 차량 → (카페) → 탑승 장소의 도로 경로를 파란 선으로 그립니다. Pleos SDK는 경로 좌표를 주지 않아 **카카오모빌리티 길찾기**로 계산한 예상 경로이며, 실제 내비 안내 경로와 다를 수 있다고 화면에 안내합니다. 차량은 옆모습 자동차 아이콘으로 표시합니다.
- **친구 준비 완료:** 친구가 웹에서 준비 완료를 누르면 차량 앱의 픽업 화면에 ‘탑승 준비 완료’가 표시됩니다. 내비 위 팝업과 별도 표시 권한은 사용하지 않습니다.
- **진행 중인 픽업 복원:** 픽미 화면을 나갔다 다시 열면 같은 초대를 복원해 친구 상태를 다시 조회합니다. 공유 중에는 홈의 ‘진행 중인 픽업 보기’로 돌아갈 수 있습니다. 앱 프로세스 종료·APK 교체·서버 재시작 이후의 영구 복원은 아직 지원하지 않습니다.
- **준비 완료·도착 안내:** 친구가 직접 ‘준비 완료’를 누르면 차량에 표시됩니다. 유효한 예상 시간이 5분 이내이면 이메일을 한 번 요청하고, 친구 웹에서는 3분·1분 이내 도착 안내를 보여줍니다.

### 딱픽업 — 가는 길 주문

- **메뉴 선택:** 돌체라떼·아메리카노·카페라떼 중 선택합니다.
- **매장 추천:** Firebase에서 매장을 읽고 **1.5 × 우회 시간 + max(0, 대기 시간 − 2분)** 점수가 가장 낮은 곳을 추천합니다. 우회 상한은 직행 시간에 따라 정하며, 모든 후보가 상한을 넘으면 많이 돌아간다는 안내를 표시합니다.
- **이동 시간 계산:** Pleos 조회값을 사용하되 일부 구간은 직선거리로 추정합니다. 조회 실패 시 시연용 기본값을 사용합니다.
- **경유지·주문:** 확인을 누르면 매장을 FIRST 경유지로 추가 요청하고, 이동 시간과 준비 시간의 차이에 맞춰 Firebase에 주문을 전송합니다. 픽미 친구 경유지가 이미 있으면 Pleos가 친구를 앞자리로 당겨 두기 때문에, 목적지 + [매장, 친구] 순서로 경로를 다시 요청해 **매장 → 친구 → 목적지** 순서를 지킵니다.
- **주문 상태 확인:** 접수·제조 중·준비 완료 등 Firebase 주문 상태 변경을 차량 화면에 표시하는 코드가 연결되어 있습니다.
- **시연용 배속:** 주문 예약은 계획상의 **1분을 실제 5초**로 처리합니다.

### 가짜매장

Firebase에 **경기도 시연 매장 3곳**이 등록되어 있습니다.

| 매장 | 지역 | 준비 시간 |
|---|---|---|
| 가상점 A | 수원 인계동 | 4분 |
| 가상점 B | 성남 판교 | 9분 |
| 가상점 C | 고양 일산 | 15분 |

매장 데이터에는 주소·좌표·준비 시간 등이 들어 있습니다. 실제 매장 주문 시스템과 연결된 것은 아닙니다.

현재 GitHub `main`의 `web/store`에는 안내 문서만 있으며, **매장 직원용 웹 화면 구현 파일은 확인되지 않습니다.**

- [ ] **친구 위치를 매장 추천에 반영:** 현재 딱픽업 추천은 확정된 친구 탑승 장소를 전달받아 계산하지 않습니다.

- **픽미:** 로컬 중계 서버와 Firebase·메일 설정이 필요합니다. 상세 내용은 [서버 안내](server/pickme/README.md)를 참고하세요.

- **협업:** 변경은 PR로 공유하고, 중요한 결정은 [결정 기록](docs/decisions.md)에 남깁니다. 비밀키와 로컬 설정은 커밋하지 않습니다.

## 비공개 메일 설정

공개 소스에는 실제 수신자 이름·주소를 넣지 않습니다. `demo-mail-recipients.json`의 주소는 발송 불가능한 테스트 예시입니다. 배포 서버의 비공개 환경 변수 `PICKME_MAIL_RECIPIENTS_JSON`에 `[{"name":"친구 1","email":"수신주소"}]` 형태로 실제 수신자를 설정합니다. Gmail 발신 계정과 앱 비밀번호도 서버 환경 변수에만 넣습니다. 이 설정이 없으면 실제 이메일 발송은 비활성화됩니다. QR·링크 재현에는 메일함 접근이 필요하지 않습니다.

팀원들은 기존 개발 저장소에서 계속 작업합니다. 제출본 갱신 시 개인정보 검사를 다시 하고, 제출 메일에는 이 저장소 주소와 확정된 최종 커밋 번호를 적습니다.
