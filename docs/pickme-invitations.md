# 픽미 초대 첫 단계

## 이번 구현

debug 홈의 픽미 카드를 누르면 시연 연락처 11명 중 친구를 검색·선택하고 초대 링크를 만듭니다. 친구 이름·만날 장소·목적지를 직접 입력하는 폼은 첫 흐름에서 제거했습니다. 친구는 웹에서 수락 또는 거절하고, 운전자 화면은 2초 간격으로 상태를 확인합니다. 딱픽업 주문·매장·공통 내비와 연결하지 않습니다.

## 초대 데이터

| 필드 | 의미 |
|---|---|
| id | 서버가 생성한 초대 식별자 |
| driverName | 초대를 보낸 운전자 표시명 (차 앱 첫 단계는 '운전자') |
| passengerName | 탑승 예정자 표시명 |
| contactId | 시연 목록에서 선택한 연락처 ID. 실제 전화번호는 저장하지 않음 |
| meetingPoint | 현재는 null. 친구 수락·위치 공유 이후 결정할 값 |
| destination | 현재는 null. 이후 기존 내비 목적지와 연결할 값 |
| status | pending / accepted / declined |
| createdAt | 생성 시각, UTC ISO-8601 |
| respondedAt | 응답 시각, 응답 전에는 null |
| expiresAt | 생성 후 24시간 |

초대 생성 응답에는 친구에게 전달할 inviteUrl이 추가됩니다. 링크의 토큰은 추측하기 어려운 무작위 값이며 URL fragment로 전달해 서버 접근 로그에 노출하지 않습니다. 서버는 토큰 해시만 메모리에 저장합니다. 운전자 세션과 친구 링크의 권한은 분리합니다.

## 이번에 하지 않는 것

- 자동 문자·카톡 발송: 링크를 복사하거나 공유 기능으로 직접 전달
- 친구의 현재 위치 수집, ETA, 준비·출발 알림
- 실제 장소 추천, 내비 경유지 변경, 매장 주문
- 운영 인증·영구 저장·인터넷 공개 배포

로컬 서버를 재시작하면 모든 초대가 사라집니다. Firebase의 최종 데이터 경로·접근 규칙과 인증은 팀 협의 후 별도로 연결합니다. 현재 Firebase 규칙에 초대 데이터를 추가하거나 주문 컬렉션을 재사용하지 않았습니다.

실행 방법: [server/pickme/README.md](../server/pickme/README.md)

## 연락처 시연 범위

친구 1·친구 2·친구 3·친구 4와 임의의 이름 7명(김민지·이도윤·박서연·최지우·정하준·강수빈·윤지호)을 `server/pickme/demo-contacts.json` 한 곳에서 관리합니다. Android와 웹이 같은 목록을 가져옵니다. 실제 기기의 연락처·통화 기록은 읽지 않습니다.

현재 초대 버튼은 링크를 생성하며 문자·카톡 자동 발송은 하지 않습니다. 수락만으로 위치를 수집하지 않습니다. 주행 상태 감지는 미연결이므로 정차 중 시험합니다. release 진입 경로는 기존 앱 흐름이며 이번 변경은 debug 시험용입니다.
