# 공통 내비 연동

픽미·딱픽업이 사용하는 Pleos NaviHelper 연결·경유지 요청·반영 확인을 관리합니다. 기능 사용 흐름은 [픽미](../../pickme/README.md)와 [딱픽업](../../pickup/README.md)을 참고합니다.

## 한눈에 보기

| 구성 | 역할 |
| --- | --- |
| `NaviRemote.kt` | SDK 연결 공유, 이동 시간 조회, 매장 경유지 추가·순서 조정 |
| `FriendWaypointController.kt` | 동승자 경유지 요청, 최종 목적지·기존 경유지 보존 확인 |
| `StoreOrderTest.kt`·`FriendWaypointTest.kt` | 경유지 순서 판단·반영 확인 관련 단위 시험 (`src/test` 아래) |

## 경유지 요청 규칙

**FIRST = 매장, SECOND = 동승자**를 기준으로 요청합니다. Pleos는 앞자리가 비어 있으면 동승자를 FIRST로 당길 수 있어, 요청한 슬롯과 실제 방문 순서를 구분합니다.

- 매장 추가 전 현재 경유지 목록을 조회합니다.
- 동승자가 매장보다 앞에 있으면 `requestRouteWithWaypoints()`로 목적지와 [매장, 동승자]를 함께 요청합니다.
- 동승자 순서 조정이 필요 없으면 매장을 FIRST에 추가 요청합니다.
- `removeWaypoint()`가 경로 전체를 취소한 에뮬레이터 관찰이 있어 순서 조정에 사용하지 않습니다.

## 반영 결과 확인

### 동승자 경유지

추가 전후 경유지·최종 목적지를 비교합니다. 유효한 좌표가 있으면 좌표를 비교하고, 좌표가 없으면 이름 반영으로 구분해 내비 지도 확인을 안내합니다. 기존 경유지가 두 곳이었다면 첫 경유지 유지 여부도 확인합니다. SDK 오류·확인 시간 초과는 실패로 처리합니다.

### 매장 경유지

현재 성공 판단에는 다음 경로가 있습니다.

- 경유지 목록에서 매장이 첫 번째이고 기존 동승자가 있으면 두 번째인지 확인
- 동승자 없이 빈 목록에 매장을 추가한 경우 경유지 개수·경로 상태로 확인
- FIRST 추가 이벤트 수신
- **추가 후 8초간 확인되지 않아도 SDK 오류가 없으면 성공 처리**

마지막 예외에서는 실제 반영·방문 순서를 확인하지 못한 상태로 주문 예약이 진행될 수 있습니다. 반면 **추가 전 경유지 목록 조회가 3초 내 응답하지 않으면 실패**하며, 매장만 추가하는 대체 동작으로 진행하지 않습니다.

## 연결과 이동 시간 조회

딱픽업 화면과 픽미 공유 서비스가 SDK 연결을 공유합니다. 한쪽 화면 종료가 다른 사용자의 연결 해제로 이어지지 않도록 화면·서비스의 사용 여부를 관리합니다.

추천용 조회는 차량 위치·목적지·각 매장까지의 시간 스냅샷을 제공합니다. 조회되지 않은 구간의 추정·기본값 적용은 [딱픽업 추천 로직](../../pickup/README.md#매장은-어떻게-고르는가)에서 설명합니다.

## 한계와 보완점

| 현재 구현·제약 | 보완 방향 |
| --- | --- |
| 동승자 확인은 이름만 가능한 환경이 있고 매장 확인에는 이벤트·개수·시간 초과 성공 경로 존재 | 좌표·이름·이벤트·미확인의 근거를 구분하고 실제 경유지·방문 순서 확인 강화 |
| 매장 확인 시간 초과도 주문 예약 해제 조건이 될 수 있음 | 미확인을 성공과 분리하고 재확인 전 주문 보류 |
| 에뮬레이터 SDK 응답·좌표 반환에 제약 존재 | 실제 주행·목적지 변경·연결 해제 상황의 통합 검증 |
