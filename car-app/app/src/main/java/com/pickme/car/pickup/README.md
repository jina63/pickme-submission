# 딱픽업 (가는 길 주문)

가는 길에 **덜 돌아가는 매장**을 골라 주고, 도착 시간에 맞춰 **음료 주문을 자동으로 보내는** 기능입니다.
운전 중에 폰을 만지지 않고, 도착하면 기다림 없이 받는 것이 목표입니다.

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 내비 경로 시간으로 매장 추천 → 경유지 추가·확인 → 시점에 맞춰 주문 전송 → 주문 상태 표시 |
| 핵심 아이디어 | 우회와 대기를 한 점수로 합쳐서 비교하고, 주문 시점을 도착 시간에서 거꾸로 계산 |
| 상태 | 에뮬레이터에서 전체 흐름(추천 → 주문 → 상태 표시) 시험 완료. 이후 추가된 '경유지 확인 후 주문 예약'과 '중복 주문 방지'는 빌드·단위 테스트만 통과했고 에뮬레이터 확인 전 |
| 같이 쓰는 기능 | 픽미(친구 픽업)와 함께 쓸 수 있음. 경로 순서는 매장 → 친구 → 목적지 |

## 사용 흐름

1. 홈에서 **딱픽업**을 누릅니다.
2. 메뉴를 고르고 **매장 추천받기**를 누릅니다.
3. 내비가 계산한 경로 시간으로 매장 한 곳이 추천됩니다. 기다림이 있는지 없는지가 가장 크게 보입니다.
4. **이 매장에서 받을게요**를 누르면 내비에 매장이 경유지로 추가됩니다. 앱이 내비 경유지 목록을 다시 읽어 매장이 제대로 들어갔는지 확인하고, **확인이 끝나야 주문이 예약**됩니다. 확인에 실패하면 추천 화면으로 돌아가 안내하고, 다시 시도할 수 있습니다.
5. 정해진 시점에 주문이 전송되고, 진행 단계(주문 전송 → 매장 접수 → 제조 중 → 준비 완료)가 화면에 표시됩니다.

- 내비 목적지나 경로가 바뀌면 추천은 자동으로 다시 계산됩니다. (주문 전에만)
- 확인 버튼을 여러 번 눌러도 주문은 한 번만 만들어집니다.
- 주문을 보낸 뒤 매장 상태를 받아 오지 못하면, 진행 화면에 머물며 안내만 합니다. (다시 주문하면 중복 주문이 되기 때문)

## 매장은 어떻게 고르나

우회와 대기를 **한 점수로 합쳐서** 가장 낮은 매장을 추천합니다.

```
점수 = 1.5 × 우회(분) + 대기(분)      (대기 2분까지는 0으로 계산)
```

- **우회**: 차 → 매장 → 목적지로 가는 시간 − 차 → 목적지 직행 시간
- **대기**: 매장에 도착했는데 음료가 아직 안 나와서 기다리는 시간 (준비 시간 − 이동 시간)
- 우회에 1.5배를 줘서 "덜 돌아가는 것"을 더 중요하게 봅니다.
- 좌표(`lat`, `lng`)가 없는 매장은 경유지로 넣을 수 없어 후보에서 뺍니다.
- 우회가 `max(10분, 직행 시간의 35%)`를 넘는 매장은 후보에서 뺍니다. 모든 매장이 넘으면 점수가 가장 낮은 곳을 추천하고 "많이 돌아가요"를 표시합니다.
- 점수가 같으면 실제 대기가 짧은 곳, 그다음 더 빨리 도착하는 곳을 고릅니다.

**예)** 직행 시간이 32분 이상이라 우회 상한이 11분 이상일 때, 우회 0분 · 대기 28분인 매장(점수 26)과 우회 11분 · 대기 0분인 매장(점수 16.5)이 있으면 후자를 추천합니다.

## 주문은 언제 보내나

```
주문 전송 시점 = 도착 예정 − 준비 시간   (이동 시간이 더 길면 그 차이만큼 기다렸다가 전송)
```

- 이동 13분 · 준비 9분 → 4분 뒤에 주문을 보냅니다. 도착하면 막 나온 음료를 받습니다.
- 이동 9분 · 준비 13분 → 바로 주문을 보내고, 도착 후 약 4분 기다립니다.
- 시간 계산은 매장 경유지 확인이 끝난 시점부터 시작합니다.
- 시연용으로 시간이 압축되어 있습니다. (1분 = 5초, 실제 값은 `OrderScheduler`의 `SECONDS_PER_PLAN_MINUTE`)

## 다른 코드와 만나는 곳

**내비 경유지**: 매장은 **FIRST** 칸, 친구(픽미)는 **SECOND** 칸에 넣도록 정해져 있습니다. 목표 순서는 매장 → 친구 → 목적지입니다. 내비 조작은 `NaviRemote`에서만 합니다. 픽미 친구 경유지가 먼저 들어가 있으면 Pleos가 친구를 앞자리로 당겨 두기 때문에, 매장을 넣을 때 목적지 + [매장, 친구]로 경로를 다시 요청해 순서를 맞춥니다(자세한 내용: `core/navi/README.md`).

**Firebase**

| 경로 | 앱이 쓰는 필드 |
| --- | --- |
| `stores/{id}` | `name`, `lat`, `lng`, `prepMin` (준비 시간, 분) |
| `orders/{id}` | `storeId`, `item`, `qty`, `status`, `etaAt`, `createdAt` |

주문 상태값(`status`)은 `ordered` → `accepted` → `making` → `ready` → `picked_up` 순서입니다. 매장 화면이 이 값을 바꾸면 차 화면의 진행 단계가 따라 바뀝니다.

## 파일 지도

| 파일 | 하는 일 |
| --- | --- |
| `pickup/ui/OrderActivity.kt` | 화면과 전체 흐름 (메뉴 → 계산 → 추천 → 주문 진행) |
| `pickup/domain/StoreRecommender.kt` | 매장 점수 계산과 추천, 내비 값으로 우회·이동 시간 계산 |
| `pickup/domain/OrderScheduler.kt` | 주문 전송 시점 계산 |
| `core/navi/NaviRemote.kt` | 내비에 경로 시간 묻기, 매장 경유지(FIRST) 추가와 확인(친구가 앞에 있으면 매장 → 친구로 다시 요청), 경로 변경 감지 |
| `core/firebase/FirebaseRepo.kt` | 매장 읽기, 주문 보내기, 주문 상태 보기 |

## 실행하고 시험하기

1. Android Studio에서 `car-app`을 열고 Pleos Connect 에뮬레이터에서 실행합니다. (JDK 21, 실행하는 컴퓨터의 `car-app/app/`에 `google-services.json` 필요)
2. 내비에서 목적지를 설정하고 **안내를 시작**합니다. 목적지가 없으면 기본값으로 계산합니다.
3. 홈에서 딱픽업 → 메뉴 선택 → 추천을 확인합니다.

| 시험 목적지 | 예상 추천 |
| --- | --- |
| 판교역 | 픽업카페 B |
| 킨텍스 | 픽업카페 C |
| 수원시청 | 픽업카페 A |

교통 상황에 따라 계산 값이 조금씩 달라져서 결과가 바뀔 수 있습니다.

- **대기 시험**: Firebase `stores/{id}`의 `prepMin`을 이동 시간보다 크게 올리면 대기가 생기고 추천이 바뀝니다. 시험 뒤에는 원래 값으로 되돌립니다.
- **주문 상태 시험**: Firebase `orders/{id}`의 `status` 값을 위 순서대로 바꾸면 진행 화면이 따라 바뀝니다.
- 에뮬레이터 차 위치는 성남 수정구에 고정되어 있습니다.

## 한계와 앞으로

- 매장 → 목적지 구간은 내비가 직접 알려 주지 못해 직선거리 기반으로 **근사**합니다.
- 주문 후 교통 상황 변화에 따른 도착 예정 시각 **갱신**은 아직 없습니다.
- 픽미와 같이 쓸 때 친구가 매장보다 가까운 경우의 **순서 선택**(친구 먼저 / 매장 먼저)은 예정 작업입니다.
- 음성 입력은 보류하고 터치로만 사용합니다. 메뉴는 3개, 결제와 가격은 없습니다.
- 경유지 확인이 끝나기 전에 화면을 나가면 주문은 예약되지 않습니다. 확인이 끝난 뒤에 나가면 주문은 계속 진행되고, 화면의 주문 상태 표시만 멈춥니다.
