# 픽미 — 동승자 픽업

동승자에게 초대 링크를 전달하고 확정된 탑승 장소를 차량 내비와 연결하는 기능입니다. 운전자 수락 후 차량 위치·도착 예상 시간과 동승자의 준비 상태를 공유합니다.

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 흐름 | 연락처 선택 → 초대 → 탑승 장소 확정 → 운전자 수락 → 경유지 확인 → 차량 정보 공유 |
| 차량 화면 | 제출용 release의 `ui/InvitationActivity` |
| 외부 연결 | [동승자 웹](../../../../../../../../../web/friend/README.md)·[중계 서버](../../../../../../../../../server/pickme/README.md) |

## 현재 구현된 범위

- 중립 표시명의 서버 등록 연락처 조회, 비공개 설정이 있는 경우 이메일 요청, 링크 복사·공유와 초대 QR 표시
- Pleos 차량 위치·목적지 자동 조회와 초대 연결
- 동승자 응답 조회 및 확정한 장소의 내비 경유지 반영 요청
- 경유지 확인 후 차량 위치·픽업 ETA·카페 경유 정보 공유
- 준비 완료 입력의 차량 화면 표시와 도착 안내 연결
- 같은 앱 프로세스 내 초대·소유 세션 복원과 공유 중 홈에서 진행 화면 복귀

## 사용 흐름

1. 내비 목적지를 설정하고 홈에서 **픽미**를 선택합니다.
2. 등록 연락처에서 동승자를 선택하고 링크를 복사·공유합니다. 이메일은 별도 메일 설정이 있는 환경에서만 사용할 수 있습니다.
3. 동승자는 웹에서 탑승 장소를 확정합니다. [장소 선택·추천 방식](../../../../../../../../../web/friend/README.md#장소-선택과-추천)을 참고합니다.
4. 운전자는 **픽업 수락 · 안내 시작**을 선택합니다. 앱은 내비 반영을 요청하고 위치 공유를 시작하며, 경유지 반영 확인 후 차량 정보를 전송합니다.
5. 동승자 웹에서 도착 정보를 확인하고 준비 완료를 입력합니다.

**제출본은 `.env` 없이 링크 복사 방식으로 확인하며, 동일 컴퓨터에서 휴대폰용과 같은 동승자 웹을 엽니다.** 응답 저장·컴퓨터 위치 조회·영상 촬영 환경의 구분은 [제출 환경 안내](../../../../../../../../../server/pickme/README.md#제출-환경과-시연-영상)를 참고합니다.

초대 기본 유효기간은 24시간입니다. release도 동일한 초대·공유 화면을 사용하며 로컬 중계 서버가 필요합니다. 설치·빌드는 [차량 앱 안내](../../../../../../../../README.md)를 참고합니다.

## QR과 진행 중인 픽업 복원

초대 생성 후 **휴대폰으로 초대 열기 · QR**을 선택하면 이메일과 같은 전체 초대 링크를 기기 안에서 QR로 생성합니다. 외부 QR 서비스로 링크를 전송하지 않으며 차량 앱의 카메라 권한도 필요하지 않습니다.

QR에는 공개 도메인의 HTTPS `/friend#초대키` 링크가 필요합니다. `127.0.0.1` 로컬 HTTP 링크는 QR로 표시해 휴대폰 연결을 대신할 수 없으므로, 기본 제출 환경에서는 같은 컴퓨터의 링크 복사 방식을 사용합니다. 공개 링크·중계 서버가 연결된 환경에서는 QR로 같은 동승자 웹을 열 수 있습니다. QR은 문자 자동 발송을 구현한 기능이 아닙니다.

픽미 화면을 닫았다 다시 열면 앱 프로세스에 보관한 초대·소유 세션을 복원하고 서버 상태를 다시 조회합니다. 공유 중 홈의 **진행 중인 픽업 보기**로 돌아갈 수 있습니다. 새 친구 선택은 기존 공유 중지 후 수행합니다. 프로세스 종료·APK 교체 후의 영구 복원은 지원하지 않습니다.

## 차량 정보 공유

- Pleos 위치·픽업 경유지 ETA를 약 5초마다 조회합니다. 오래되거나 유효하지 않은 ETA는 전송에서 제외합니다.
- 딱픽업 카페가 동승자보다 앞에 있는 것으로 확인되면 카페 이름·좌표·경유 전/도착/경유 후 상태를 공유합니다. ETA는 매장 대기 시간을 포함하지 않습니다.
- 공유는 최대 1시간이며 초대 만료 시점에 따라 제한됩니다. 공유 중지·최근 앱 목록에서 앱 종료·공유 시간 만료 시 종료합니다.
- 내비 반영 기준과 연결 공유는 [공통 내비 안내](../core/navi/README.md), 웹 표시·지연 처리는 [동승자 웹 안내](../../../../../../../../../web/friend/README.md#차량-정보-표시)를 참고합니다.

## 준비 상태와 도착 안내

동승자의 **준비 완료** 입력을 서버에서 조회하여 차량 픽업 화면에 표시합니다. 실제 도착·탑승 자동 감지는 아닙니다. 내비 위 팝업과 별도 오버레이 권한은 사용하지 않습니다.

도착 메일의 발송 조건·중복 제한은 [서버 메일 처리](../../../../../../../../../server/pickme/README.md#이메일-처리), 3분·1분 웹 안내는 [동승자 웹](../../../../../../../../../web/friend/README.md#차량-정보-표시)에서 관리합니다.

## 파일 지도

| 위치 | 역할 |
| --- | --- |
| `ui/` | 초대·응답·수락 화면, `InvitationQr`, `InvitationSessionStore` |
| `sharing/` | 내비 정보 조회·차량 정보 전송·카페 경유 판단 |

## 한계와 보완점

| 현재 구현·제약 | 보완 방향 |
| --- | --- |
| 시연·로컬 연락처 사용. 실제 전화번호부·자동 문자 미연결 | 실제 연락처·초대 채널 연동 범위 정리 |
| 화면 재진입은 같은 프로세스에서 복원하지만 프로세스 종료 후 복구는 없음 | 영구 초대 복원과 공유 재개 검증 |
| 준비 완료는 직접 입력, 매장 대기는 친구 ETA에 미포함 | 실제 탑승 확인과 준비·대기 정보 연계 |

이전 `legacy/PickupRequestActivity`는 삭제되었으며 홈은 항상 `InvitationActivity`를 실행합니다. 배포 구성은 차량 앱 문서, 서버 재시작·세션 제약은 서버 문서에서 관리합니다.
