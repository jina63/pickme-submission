# 픽미 (친구 픽업)

친구에게 **링크 하나**만 보내면, 친구는 앱 설치 없이 **탈 곳을 직접 고르고**,
차는 그 장소를 **순정 Pleos 내비 경유지**로 넣어 데리러 가는 기능입니다.
친구는 차가 어디쯤인지, 몇 분 남았는지 폰에서 바로 확인합니다.

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 친구 초대 → 친구가 탑승 장소 확정 → 운전자 수락 → 내비에 친구 경유지 추가 → 차 위치·도착 예정 시간 공유 → 친구 준비 완료 표시 |
| 핵심 아이디어 | 친구는 **웹 링크만**으로 참여하고, 차량 쪽은 **새 내비를 만들지 않고 순정 내비에 경유지만** 넣습니다 |
| 같이 쓰는 기능 | 딱픽업과 함께 쓰면 경로는 **매장(FIRST) → 친구(SECOND) → 목적지** 순서를 유지합니다 |
| 현재 범위 | 로컬 중계 서버를 함께 켜야 동작하는 시연용 프로토타입 (debug·release 동일) |



## 진행 중인 픽업 다시 보기

픽미를 나갔다 다시 열면 같은 초대 정보를 복원하고 서버에서 친구 준비 완료 상태를 다시 조회합니다. 공유 중에는 홈의 **진행 중인 픽업 보기**를 사용합니다. 새 초대는 기존 공유 중지 후 **다른 친구 선택하기**으로 만듭니다. 재진입만으로 초대나 이메일을 다시 보내지 않습니다. 앱 프로세스 종료·APK 교체·서버 재시작 후의 영구 복원은 아직 지원하지 않습니다.

## 초대 전달 방식

서비스 목표는 전화번호로 문자 초대 링크를 보내는 것입니다. 현재는 문자 발송을 구현하지 않아 **시연 영상에서 이메일로 링크를 전달**합니다. **심사위원 직접 재현용 QR 표시를 제공**하며, 메시지로 받은 링크를 열었을 때와 동일한 친구 웹 화면으로 진입하기 위한 보조 수단입니다. 메일 기능은 유지하고, QR도 같은 초대 링크를 사용합니다. 휴대폰 재현에는 공개 HTTPS 친구 웹과 연결된 중계 서버가 필요합니다.

## 사용 흐름

**운전자 (차 화면)**
1. 순정 내비에서 목적지를 정하고 안내를 시작합니다.
2. 홈 → **픽미**를 누르면 현재 위치와 목적지를 내비에서 자동으로 가져옵니다.
3. 연락처에서 친구를 고르고 **초대**를 보냅니다. (이메일 발송 또는 링크 복사·공유) -> 추후 핸드폰과 연결했을때 핸드폰의 전화번호목록을 가져와 문자로 발송하는 서비스로 발전될 수 있음.
4. 친구가 탈 곳을 보내면 화면에 장소가 표시됩니다.
5. 위치 공유 여부를 고르고 **수락**하면, 친구 장소가 내비에 **경유지**로 들어갑니다.

**친구 (폰 브라우저)**
1. 받은 링크를 엽니다. 앱 설치나 회원가입은 필요 없습니다.
2. **장소 검색 · 현재 위치 · 주변 추천 · 지도 핀 옮기기** 중 편한 방법으로 탈 곳을 정해 보냅니다.
3. 운전자가 수락하면 차 위치와 탑승 장소까지 남은 시간이 지도에 보입니다.
4. 탑승 장소에 도착하면 **도착했어요 · 준비 완료**를 누릅니다.

## 친구는 어떻게 탈 곳을 고르나

- 내 위치나 검색한 장소를 기준으로 **반경 500m 안**에서 팀이 등록한 후보와 주차장을 가까운 순서로 **최대 3곳** 추천합니다.
- 추천이 마음에 들지 않으면 지도 핀을 직접 옮겨 정할 수 있습니다.
- 현재는 직선거리 기준이며, 차량 진입 방향·유턴·정차 가능 여부까지 판단하지는 않습니다.

## 차와 친구는 무엇을 주고받나

| 시점 | 차 → 친구 | 친구 → 차 |
| --- | --- | --- |
| 초대 | 초대 링크, 함께 갈 목적지 이름 | — |
| 장소 확정 | — | 탈 곳 이름·좌표 |
| 이동 중 (약 5초마다) | 차 위치, 탑승 장소까지 남은 시간(내비 값) | — |
| 카페를 들를 때 | "카페에 들렀다 가는 중" 상태, 카페를 반영한 예상 시간 | — |
| 도착 | — | 준비 완료 → 차량 앱 픽업 화면에 "탑승 준비 완료" 표시 |

- 남은 시간은 앱이 따로 계산하지 않고 **Pleos 내비가 알려 주는 경유지 남은 시간**을 그대로 씁니다.
- 내비 시간에는 카페에서 음료를 기다리는 시간은 포함되지 않습니다.
- 공유는 운전자가 동의했을 때만 시작하고, **공유 중지**를 누르면 친구 화면에서 차 위치와 시간이 사라집니다.

## 구성

```
차량 앱 (Pleos)            로컬 중계 서버              Firebase                 친구 웹
pickme/ui      ──초대·수락──▶ server/pickme ──저장──▶ pickmeInvites   ◀──응답── web/friend
pickme/sharing ──위치·시간──▶               ──저장──▶ pickmeLive      ──표시──▶ (Hosting)
pickme/banner  ◀──준비 완료──               ◀──읽기── pickmeReady     ◀──버튼──
core/navi      ──친구 경유지(SECOND)──▶ 순정 Pleos 내비
```

| 사용 기술 | 용도 |
| --- | --- |
| Pleos NaviHelper SDK | 내비 목적지·위치 읽기, 친구 경유지 추가, 경유지 남은 시간 |
| Firebase Realtime Database · Hosting · 익명 인증 | 초대 응답·차 위치 공유, 친구 웹 배포 |
| Node.js 중계 서버 | 초대 생성, 이메일 발송, 차 위치 업로드 중계 |
| Leaflet + OpenStreetMap | 친구 웹 지도 |
| 카카오 로컬 API | 주변 주차장 추천 (키가 없으면 OpenStreetMap으로 대체) |

## 실행하고 시험하기

1. `server/pickme/.env`를 준비합니다. 항목 이름은 `.env.example`에 있고, 실제 값은 Git에 올리지 않습니다.
2. 서버를 켭니다. 처음 한 번은 `server/pickme`에서 `npm install`이 필요합니다.
   ```bash
   node --env-file=server/pickme/.env server/pickme/server.mjs
   ```
3. Pleos Connect 에뮬레이터에 앱을 실행합니다. (Android Studio ▶ Run 또는 `apk/` 폴더의 release APK)
4. 내비 목적지 설정 → 홈 → 픽미 → 초대 → 폰에서 링크 열기 → 탈 곳 보내기 → 차에서 수락 → 폰에서 준비 완료

- 서버를 껐다 켜면 이전 초대는 사용할 수 없으니 **새로 초대**합니다.
- QR은 초대 화면에서 **휴대폰으로 초대 열기 · QR**을 눌러 확인합니다. 공개 HTTPS 초대 링크가 필요하고 로컬 전용 주소는 QR로 제공하지 않습니다. 휴대폰 실물 스캔 확인은 아직입니다.
- 메일함에 이전 초대가 남아 있으면 헷갈리기 쉽습니다. 링크 주소의 `#` 뒤 글자가 차 화면의 링크와 같은지 확인합니다.

## 확인한 것 / 아직 확인하지 못한 것

| 항목 | 상태 |
| --- | --- |
| 초대 → 친구 장소 확정 → 차량 수락 → 친구 경유지(SECOND) 추가 | 에뮬레이터에서 확인 |
| 친구 웹에 차 위치·남은 시간 표시, 공유 중지 시 숨김 | 확인 |
| 카페 경유 상태(들르기 전 → 도착 → 지남) 친구 웹 표시 | 시연 데이터로 확인 |
| 실제 주행에서 남은 시간이 줄어드는 모습, 경유지 도착 처리 | 미확인 (에뮬레이터 차량이 움직이지 않음) |
| 도착 5분 전 이메일 | 실제 주행 미확인 |

친구 준비 완료는 차량 앱의 픽업 화면에서 확인합니다. 내비 위 팝업과 별도 표시 권한 설정은 사용하지 않습니다.

## 한계와 앞으로

- 친구 초대·위치 공유는 **로컬 중계 서버**가 있어야 동작합니다. 실제 서비스에서는 서버를 인터넷에 올리고 사용자 인증을 붙여야 합니다.
- 친구 응답을 바로 보려면 운전자가 앱을 내비 옆 **분할 화면**에 띄워 두는 방식이 실제 차량에서도 안전합니다. 다음 단계에서 좁은 칸용 수락 카드와 알림음을 추가할 계획입니다.
- 음성(STT·TTS)이 열리면 "○○님이 탑승 장소를 보냈어요" 같은 음성 안내를 붙일 예정입니다.
- 탑승 장소 추천에 도로 방향·정차 가능 여부를 반영해야 합니다.
